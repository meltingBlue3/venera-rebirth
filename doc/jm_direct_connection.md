# JMComic 直连

在「设置 → 网络」开启「JMComic 直连」。默认关闭，开启后新请求生效；已开始的请求取消后重试。先安装上游 JM 图源（`key=jm`，当前适配版本为 1.4.0），无需手工修改已安装的 `jm.js`。应用加载图源时安装自己的兼容层，图源更新不会覆盖该文件；未来图源改变网络接口时仍需重新验证兼容性。

## 连接和换线

- 对 JM 配置入口、API 和图片使用直接连接，绕过应用代理。其他域名继续沿用原有配置；系统 VPN/TUN 路由仍由系统决定。WebView 和外部浏览器不在覆盖范围内。
- 使用阿里 DNS、DNSPod 的 HTTPS JSON DNS 接口，分别查询 A/AAAA。解析服务通过内置地址启动，保留它们的 HTTPS 主机名和证书验证。优先尝试阿里，失败后尝试 DNSPod，两者均失败再尝试系统 DNS。每个提供方的两类查询并发，各限时 2 秒；系统解析也限时 2 秒。DNS 缓存遵守返回 TTL，上限 300 秒，同时合并同一主机的并发解析。手工「DNS 覆盖」优先。
- JM 连接始终保留 SNI、原 URL 的 Host 和证书验证，即使全局调试设置关闭 SNI 或忽略证书错误，也不会削弱这些请求的校验。重定向逐跳重新选路，跨 origin 移除认证头和手工 Cookie。
- 图源启动时先使用缓存域名或内置列表。启用图源的「启动时刷新域名列表」后，并发读取北京、香港、新加坡三个官方配置入口，采用首份有效列表；HTTP、解密、JSON 或空列表失败均保留旧列表。设置中的手动刷新仍需点「应用」才替换列表。
- 已知的只读 API 失败后最多尝试三个域名。只对传输错误及 HTTP 408、500、502、503、504 换线；认证失败、限流及协议错误直接返回。失败域名冷却 60 秒，成功线路优先用于后续请求。用户手动更改 API 线路会清除这一临时偏好，保存的线路选项不会被自动改写。
- 登录、收藏、评论等 POST 保持原图源行为，只发送一次，不因超时跨域重放。不同域名的 Cookie 仍按原有域名隔离，不把账号 Cookie 复制给其他入口。
- 图片设置从 `/setting` 单独取得。更改「图片分流」后，下次封面或正文加载前会应用新设置；配置失败保留缓存图片域名，并对同一分流的自动刷新冷却 60 秒。显式刷新不受该冷却限制。
- 封面、头像、正文和逐页下载的 `/media/albums/`、`/media/users/`、`/media/photos/` 请求最多尝试三个图片域名，保留路径、查询参数、请求头与原图源解扰配置。每次重试重新缓冲，防止把两台服务器的部分图片拼在一起。成功图片线路在本次运行中复用，手动切换到其他图片域名时优先尝试新域名。

JM 每次原生发送的总超时为 12 秒，重定向逐跳计算且受跳数上限约束；API 和图片各最多三次尝试。启动配置、图片配置和业务请求是不同操作，首次使用可能额外等待配置获取。取消、401 和 429 不进行图片换线。

缓存仅在图源自己的数据中增加 `jmNetwork` 字段，保存 API 列表、成功 API 域名和图片入口。保留 `jm` 标识、漫画/章节 ID、账号、收藏、历史及下载记录格式，无需数据迁移。关闭开关后使用原图源请求逻辑；兼容层只为原图源未初始化的 API 列表补静态初值。

## 参考和边界

配置发现和候选域名参考 [JMComic-Crawler-Python 的固定版本](https://github.com/hect0x7/JMComic-Crawler-Python/blob/fd8953025db5b844f1b7f025d063f544e61a2dbd/src/jmcomic/jm_config.py)。[JMComic-qt 的连接配置](https://github.com/tonquer/JMComic-qt/blob/c12629508bb43404ff667cb6f36f9d97f782390b/src/server/req.py)提供了 DoH、解析覆盖和 ECH 的实现参考。本次沿用锁定的 rhttp，没有增加原生依赖，也没有实现 ECH 或 HTTP/3 专用选路。

DoH 和入口换线能改善解析异常及单域名不可用，不能保证解决按 SNI 阻断、全部 IP 不可达或服务端地区限制。当前网络的一次成功不代表中国大陆各地区、各运营商都能访问。完整调研及 ECH 路线的限制见 [既有调研](jmcomic_direct_connection_research.md)。

## 验证

```bash
node --test test/jm_network_test.cjs
flutter test --no-pub
flutter analyze --no-pub lib test patch
git diff --check
```

JavaScript 用例通过隔离的图源协议桩验证开关、初始化、配置损坏、换线、缓存、手动选择、写操作不重放和图片配置保留。Dart 用例验证真实适配器配置、DNS TTL/并发/回退、逐跳重定向和图片流中断后的完整重试。它们不依赖站点或真实账号。

可选的原生实时探测只访问域名配置和 `/setting`，使用真实上游脚本与宿主加解密、DNS、HTTP 接口；缓存和设置使用内存数据，不读取真实账号和收藏。先构建目标桌面平台，并让测试进程能找到构建目录中的原生动态库。以下为 Windows PowerShell 示例；`flutter` 需在 PATH，NuGet/C++/Rust 工具链按开发环境配置：

```powershell
flutter build windows --debug --no-pub
$env:PATH = (Resolve-Path 'build/windows/x64/runner/Debug').Path + ';' + $env:PATH
$env:JM_DIRECT_LIVE_TESTS = '1'
$env:JM_SOURCE_PATH = Join-Path $env:TEMP 'jm-source-probe.js'
Invoke-WebRequest 'https://raw.githubusercontent.com/venera-app/venera-configs/40be5f6e14bb9303ea3b1c512932b91cdd01d0b8/jm.js' -OutFile $env:JM_SOURCE_PATH
flutter test --no-pub test/jm_live_connection_test.dart
Remove-Item Env:JM_DIRECT_LIVE_TESTS
Remove-Item Env:JM_SOURCE_PATH
```

2026-10-26 的验证：Windows x64 调试构建成功（退出 0）。14 项 JS 测试、28 项常规 Flutter 测试和原生实时测试通过（退出 0）；常规测试另外跳过 12 项需显式启用的测试。源码分析只有开发指南记录的 8 条既有弃用信息（退出 1），差异检查通过（退出 0）。

Node HTTPS 探测从官方北京配置入口取得 HTTP 200；首个 API 的 `/setting` 返回 HTTP 200，成功解密出 `img_host`。原生实时测试实际执行 QuickJS → rhttp → DoH → JM 的配置及 API 请求；应用代理故意设为不可用的回环地址，仍成功取得并解密图片配置，验证了绕过应用代理的行为。

另行启用既有 `image_download_task_test.dart` 后，6 项原生下载断言通过，但 Windows 清理临时目录时因缓存数据库句柄未关闭而失败（命令退出 1）。该测试与缓存数据库生命周期未在本次改动中调整；普通测试按原规则跳过它。
